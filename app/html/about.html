What I value

Code readability and maintainability

As a developer I always am thinking about whether what I am making can be understood when I want to add a feature in the future. This is important because software is never really finished, so you should always consider a future where someone else wants to change what you have made or you want to make a change after you inevitably forget how the system works.

Clear and simple user experience

The user experience is what really matters. It is possible to have a good user experience with a complex interface that requires time to learn, but usually that good user experience can be upgraded to a great user experience by ensuring it is clear and simple.

Maximal functionality with limited flashiness

People use software for some function. Whether that function is getting information, communication, data manipulation, or entertainment, the important part is the functionality. Therefore it is obvious that software should provide as much functionality as reasonably possible. Furthermore, I also think it is important to limit flashiness. When I was looking at other developer's websites one thing that always bugged me was the flashiness. Some websites looked interesting, but were impossible to actually read; others had cool effects, but caused my computer to struggle to render the page. All of the flashiness was actually getting in the way of providing information about the person, which is the intended functionality of a personal website. Learning from this, when designing software I always make sure that the flashiness provides functionality past looking cool.
